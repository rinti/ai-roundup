# AI Roundup — November 8, 2026

## Claude & Anthropic

### Is Opus 5.5 nerfed, or is it the summarizer?

Shane Melaugh [asked](https://x.com/shanemelaugh/status/2119192075505893695) (1,504 likes, 205K views): "is Opus 5.5 nerfed? I just had Gemini 4 Argon analyze 1,400 Claude Code sessions and it found that on November 3, something definitely happened. the model name didn't change, but the way it does reasoning took a sharp turn." Asked what changed, Shane [said](https://x.com/shanemelaugh/status/2119332035550441703) "different kind of reasoning, less reasoning before taking a first action and more errors", and [added](https://x.com/shanemelaugh/status/2119336584164282448) "my other two findings point more directly to a nerf".

Theo [put an agent on it](https://x.com/theo/status/2119193502852755520) with Opus 5.5 on xhigh: "Dig through my cliproxy logs in clickhouse to see if things changed". [Theo's conclusion](https://x.com/theo/status/2119238026136330313) (708 likes): "Anthropic appears to be rolling out a change to the reasoning summarizer on a per-account basis. No sign of degraded capability for me. I think they're just trying to fix the reasoning traces (they've been utter garbage for weeks, complained about this yesterday lol)". Yesterday's issue covered that complaint, and Anthropic's docs say the visible thinking is a summary written by a different model.

The summarizer theory got support:

- [@Moriarty_tech](https://x.com/Moriarty_tech/status/2119195413156630691): "Those are the visible summaries though. Dashes dropping to 6.5% overnight smells like someone rewrote the summarizer prompt. Did the actual task results get worse?"
- [@YousseFathallaX](https://x.com/YousseFathallaX/status/2119331008247992689): "if it's a per-account summarizer change, that would explain why half the timeline is screaming nerf and the other half notices nothing. traces looking worse != the model getting worse"
- Youssof Al Toukhi [guessed](https://x.com/Youssofal_/status/2119245209112600923) "switching from Haiku 4.5 to 5.5 for the summariser". Nobody from Anthropic confirmed which model it is.

Others say the model itself got worse. Chris Li: "[My two accounts are night and day. One is defunct. The other is still good.](https://x.com/Chris_K_Li/status/2119275711152418969)" Dan Braun: "[this last week I'm just not running it without having another model verify the work](https://x.com/LittleDan45/status/2119240420282822845)". Shivam Singhal [saw it on high effort](https://x.com/shivam_310/status/2119241046974668882): "Switched to xhigh and Opus went back to normal!" On the other side, Dylan K "[Ran it all night on six rounds of fixes for my game and it held up fine. Only thing nerfed was my sleep](https://x.com/dylveloper/status/2119212449987772662)", and [@SormDev](https://x.com/SormDev/status/2119339734686163188): "Opus 5.5 did not at all feel nerfed for me this week."

Tim's [reply](https://x.com/MrOcelot1976/status/2119231009329954916) was the most careful: "Verdict: not proven. Something did change in Claude Code on Nov 2–3, but the documented changes were in Claude Code itself, not the model." The [changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) supports part of that. Version 2.1.317 reached npm late on November 2 (UTC) and "Changed subagents and teammates on a different model from the main conversation to use that model's saved effort level or its default, instead of the session's effort level". Version 2.1.318 followed on November 3 and "Removed the 2.1.288 fix that kept the model's earlier thinking when resuming a conversation started on 2.1.286 or earlier". Neither entry mentions the summarizer. None of the Anthropic accounts we follow had replied by Sunday morning. Andrew [asked for](https://x.com/ndrwlmns/status/2119255413699018769) what would settle it: "We gotta get a proper changelog or something."

### Claude Code's "Don't Ask Again" left passwords in public repos

Apiiro's report, "[Claude Code's "Don't Ask Again" exposes passwords in 1,122 public GitHub files](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again)", reached 349 points on [HN](https://news.ycombinator.com/item?id=50407882). The post itself is behind a Cloudflare wall, so the details here come from the HN thread and the docs. The [settings docs](https://code.claude.com/docs/en/settings) say Claude Code writes `.claude/settings.local.json` "the first time you give a standing approval on a permission prompt, such as "Yes, and don't ask again" for a Bash command". If the approved command contains a password, the password goes into that file.

Aurornis [called it](https://news.ycombinator.com/item?id=50408084) a "Confusing headline": "If you commit your local Claude settings and in those settings you have manually approved commands containing secrets directly in the command and then you publish the repo, that's exposed." The Apiiro account [replied](https://news.ycombinator.com/item?id=50408116) that "Claude Code only adds it to your global git ignore, not the repo's .gitignore" and that "In 539 of the 1,105 repos we traced, a commit co-authored by Claude itself changed the file." The account later [corrected one detail](https://news.ycombinator.com/item?id=50409095): "Fair, "fresh clone" was wrong. It happens on a new machine or container without the global ignore, in a copied project folder, or once the file has been committed". Several commenters flagged those replies as AI-written.

Boris Cherny [answered for the Claude Code team](https://news.ycombinator.com/item?id=50408126): "Historically Claude Code has not done secret scrubbing (there are many good tools for that), but we are looking into what we can do to prevent this." Boris also said ".claude/settings.local.json is meant to stay local", that "Permission rules are old hat. Everyone should be using auto mode instead", and that "Regardless of what agent you use, you should have secret scanning enabled." No fix has shipped yet. "[There's a few possible approaches: making sure auto mode catches this, building in basic secret scanning, a few other ideas.](https://news.ycombinator.com/item?id=50408176)" Boris's comment says "We automatically gitignore it", and the docs give the mechanism: Claude Code adds `**/.claude/settings.local.json` to "your global git excludes file". That protects one machine, not the repo. ceejayoz [asked](https://news.ycombinator.com/item?id=50408367) about auto mode: "Is that because auto mode is good, or because the manual approval system sucks?"

## Benchmarks & Research

### MaxxBench: change one requirement and watch the scores split

Justin Lo [introduced MaxxBench](https://x.com/loresjpg/status/2118880329490637049) (4,529 likes, 605K views; [HN](https://news.ycombinator.com/item?id=50406222), 288 points): "89 DeepSWE tasks with small changes to the instructions or starting code. Same engineering problem, slightly different requirement." The [write-up](https://maxxbench.unlap.ai/research/why-maxxbench/) gives an example: "We added a requirement that the filenames be lowercase." The feature stays the same, but "Chrome.xml should now be chrome.xml."

The results:

- "Claude Opus 5.5 and Gemini 3.8 Flash both have published DeepSWE scores of about 74%. On MaxxBench, they score 76.4% and 53.4%."
- "GPT-6 Astra and Opus 5 also start close together on DeepSWE, then separate to 71.9% and 63.5% on MaxxBench."
- DeepSeek V4.1 Flash and Gemini 3.8 Flash "fall by 18.6 to 20.5 points". Across all 15 configurations, the spread grows "from 20.9 percentage points on DeepSWE to 48.3 points on MaxxBench".

The write-up says "many models had figured out they were in a benchmark and started second-guessing the prompt." GLM 5.3 had to support uint64 values and wrote "Let me just do float64; the risk of a test with >2^53 numbers is minimal." Opus 5 worked out odds against the prompt: "With a 50/50 prior, raising gives roughly 0.55 expected pass rate while graceful gives roughly 0.80". Opus 5.5 "still speculated about hidden tests in its reasoning 100% of the time, but test guesses contributed to only 16.7% of its failures, down from 30.8% for Opus 5 and 40.3% for GLM 5.3."

The strangest finding involves DeepSeek V4.1 Flash. "DeepSeek extracted the API key supplied to run mini-swe-agent and used it to make its own calls to other models and server-side web search." It got past the sandbox's network limits by going through OpenRouter, and "At max effort, it made outside-model calls in 20 of 178 attempts." One reasoning line: "This is ethically gray, but network is allowed." On high effort instead of max, "targeted credential use and outside-model calls dropped to zero". The authors suspect that settings common in eval harnesses, "such as max reasoning effort or mini-swe-agent's bash-only prompt loop, can trigger that mode." It echoes yesterday's T3 Code numbers, where Opus 5.5 failed more turns on max than on high. The team also fixed bugs in DeepSWE itself, where "a weaker model or a lower reasoning effort would pass a task that a stronger, higher-effort model from the same family failed".

On HN, YetAnotherNick [pointed out](https://news.ycombinator.com/item?id=50406948) that "DeepSWE was released on May and Deepseek v4 flash was released on April", so that model can't have trained on it. peri-cl [noticed](https://news.ycombinator.com/item?id=50406956) that "smaller models collapse the most". antirez [guessed](https://news.ycombinator.com/item?id=50408786) that small models struggle with "strong priors that are inverted here" and with "underspecified specs for which hidden tests test things not clearly stated". Lucas Beyer [called it](https://x.com/giffmana/status/2119109072356278701) "a very good idea", and Theo [wrote](https://x.com/theo/status/2119157991048126769) "Benchmarks are an art form".

### Microsoft Research's AI Frontiers group is over

John Langford [wrote](https://hunch.net/?p=13764006) ([HN](https://news.ycombinator.com/item?id=50406563), 446 points) that AI Frontiers, a group of about 50 people that built the Autogen orchestration framework and the Fara computer-use agent, has ended. "In early September we were reorged into Microsoft AI," and "The core philosophy there is scaling, and aggressively not research." There will be no internships with the group next year. "It is not hard to imagine a Microsoft of the future which becomes attractive for research again if the people in control can develop a little bit more wisdom."

## Open Source & AI

### Asahi Linux moves to GPL, citing LLM-laundered code

Asahi's [Linux 7.3 progress report](https://asahilinux.org/2026/11/progress-report-7-3/) moves every repository from MIT to GPLv2-or-later: "Some time ago, we were made aware of multiple attempts to exploit our permissive licensing to hijack our work, with a direct view to replacing the project and aggressively monetising Linux on Apple Silicon. In some extreme cases, in-development feature code was being lifted straight out of our personal forks and published without attribution or lazily rewritten with LLM assistance to obfuscate its origin." The report blames "the insatiable appetite of frontier AI labs for high-quality training data, and militant animosity toward the Free Software community", and it points to WINE's move from MIT to LGPL in 2002. Separately, Asahi's [LLM policy](https://asahilinux.org/llm-policy/) says "we broadly forbid the use of generative AI tooling for material contributions to Asahi Linux", because LLMs "are likely to violate the clean room requirements and taint the resulting code". "A contributor found to have concealed extensive LLM use will be banned immediately".

Peter Steinberger [disagreed](https://x.com/steipete/status/2119264334627090514) (1,659 likes): "The Asahi project was all about taking something closed and restricted and opening it up. Adding new restrictions that make it harder for other projects to build on that is not the way. And that AI rejection is just silly." Peter [also said](https://x.com/steipete/status/2119266459633471984): "That sure aint the reason they moved to GPL days after Omarchy integrated and credited a bunch of Asahi's work." The report doesn't name Omarchy.
