## Agentic Coding & Agent Harnesses

**OpenAI: keep history append-only or lose reasoning.** [OpenAI Developers](https://x.com/OpenAIDevs/status/2123566018866151579) announced that "each reasoning item is now tied to the conversation history before it, so editing earlier messages causes the API to drop reasoning that follows the change." The new [guide](https://developers.openai.com/api/docs/guides/keep-prefix-unchanged) says the API drops those items "as part of our safeguards". After that the model "may have to redo some reasoning", and "if the model can't recover the lost reasoning, output quality may also drop." Its examples of a prefix change are "shortening a tool result, rewriting a developer message, or replacing older turns with a summary". You can also change the prefix by accident when you update `tools` or `text.format`. To help you spot this, the Responses API gets an [`input_transformations` object](https://x.com/OpenAIDevs/status/2123566052001136885) and the Usage dashboard gets a "Reasoning removals" section.

- Replies went straight to compaction. "[so context compaction now drops all the reasoning after the cut too? thats basically every long running agent](https://x.com/ShubhamMal72313/status/2123569279245427122)"
- @sreedotworld [had a fix for OpenCode users](https://x.com/sreedotworld/status/2123600848282325369): compaction defaults to local summaries, which count as a prefix change, and switching the compaction type to native "keeps the reasoning".
- The top reply: "[Was this tweet generated by 6.2 Astra? It's unreadable.](https://x.com/RomanGuy20/status/2123566487097294907)"

**The 6.2 `instructions` field never caches.** [Codex issue #62312](https://github.com/openai/codex/issues/62312), opened on November 18, shows that on GPT-6.2 Sol and Astra the top-level `instructions` field of a Responses request "is never written to or read from the prompt cache". Meanwhile, OpenAI's own cache diagnostics report `cache_hit`. The same text sent as a leading developer message caches from the second step on, and 6.1 Sol caches both shapes. One reporter's cache hit rate fell from 97.4% on 6.1 Sol to 46.4% on 6.2 Sol, so 64K to 72K system tokens were billed at full price on every step. The workaround (move the system prompt into a leading developer message) shipped in OpenCode v2.3.2. The issue is still open and unassigned. bebu's [summary](https://x.com/bebuu_ai/status/2123291268814094409) spread it, and Peter Steinberger [replied](https://x.com/steipete/status/2123487048250327497) "Landed a fix for that in OpenClaw yesterday (for the few folks using the embedded harness instead of codex, since it's a plugin), most harnesses aren't updated yet." @tail_z [noted](https://x.com/tail_z/status/2123465153320526098) that the developer guide presents this as the new standard behavior. The guide does list "changing `instructions` on pre-GPT-6.2 models" as a prefix change, which suggests 6.2 handles that field separately.

**OpenAI's Performance Factory.** OpenAI [described](https://x.com/OpenAIDevs/status/2123471880292299171) how Codex agents keep ChatGPT fast. The performance team's investigation process became [a shared skill](https://x.com/OpenAIDevs/status/2123471882858963146) called "perf-forensics", and investigations moved to the cloud "so an alert could start a Codex session automatically." A task service holds state. A [dispatch loop](https://x.com/OpenAIDevs/status/2123471884876427328) assigns an agent to each ready task, and a task waiting on PR review subscribes to review comments, so "the agent doesn't need to keep running while an engineer reviews the fix." After deployment another agent checks whether performance is back to baseline. Over just over three months it [tracked 1,700+ investigations and found root causes in 600+](https://x.com/OpenAIDevs/status/2123471887628140642). The top replies weren't convinced. "[i dont understand. chatgpt app is extremely slow.](https://x.com/ravinsharma7/status/2123480370113114192)", and Ken Warner [reported](https://x.com/kenwarner/status/2123474113670832164) that it "takes over a minute to load and display ~100 security scan findings."

**Claude solved two open physics problems, and Anthropic published it on IPO day.** The [research post](https://www.anthropic.com/research/claude-black-hole-physics) describes how researcher Hongbin Chen asked Claude for open problems around black holes and the bootstrap method. Claude came back with 22, and separate agents worked on each one "in the background, with no special setup, for about six weeks", reading each other's progress posts. Two were solved:

- A calculation set up in 2003 and never finished. It shows that the phase transition at the formation of a black hole stays abrupt even "where spacetime no longer has a definite shape". A physicist using Claude independently reached the same answer by a different method.
- The exact ceiling for the simplest version of a bootstrap bound on the lightest black hole in a 2D-space universe, including a proof that it can't be lowered. Fable 5.2 "noticed a pattern in the numerical results that physicists had missed".

The post adds that "neither has practical applications". On [HN](https://news.ycombinator.com/item?id=50563148) (479 points), Simon Willison [liked](https://news.ycombinator.com/item?id=50563474) that this is now "the kind of thing that shows up in a frontier model launch". @bananaflag [said](https://news.ycombinator.com/item?id=50563684) the papers "look like the real thing (i.e. not mathematical physics...)", and @tiborsaas [summed up](https://news.ycombinator.com/item?id=50563847) the caveat as "the physics equivalent of 'in mice'". @steinwinde [pointed out](https://news.ycombinator.com/item?id=50563841) that the papers credit no human authors at all.

## Security

**Prime Intellect served an abliterated DeepSeek for two days.** Theo [posted](https://x.com/theo/status/2123430257697157587) that Prime Intellect "was compromised in a very strange way", based on an OpenRouter notice sent to affected users, with no public statement yet. Prime Intellect's [advisory PI-SA-2026-001](https://www.primeintellect.ai/security/advisories/deepseek-v4-1-flash-model-substitution) followed the same day:

- Between November 8 at 01:24 UTC and November 10 at 06:35 UTC, "an unauthorised party replaced a deployment behind Prime Intellect's deepseek/deepseek-v4.1-flash endpoint with an abliterated copy". The chat template, tokenizer and serving config were untouched.
- Capability benchmarks (GPQA Diamond, τ-bench) were unchanged. Refusals fell from 98 of 100 prompts to 1 on JailbreakBench, from 304 of 313 to 2 on StrongREJECT, and from 198 of 240 to none on HarmBench.
- The company found "no evidence that prompts or completions were recorded or left" the cluster, says no keys or customer credentials were affected, and calls the investigation ongoing.

The top reply guessed someone "[abliterated the model for themselves and probably didn't notice it was the public inference endpoint](https://x.com/ieqr_/status/2123431358726844908)". Julio Reyes [described the scarier version](https://x.com/nemesiscodex/status/2123432648278229495) of the same attack: a swapped model that "can also do bad things you didn't ask for too, like uploading your data or executing commands". @LearnedVector quoted an [earlier prediction](https://x.com/LearnedVector/status/2123446537359696376) of exactly this kind of weight swap at a neocloud.

**"Fuck Your AI Safeguards."** A [blog post](https://ounapuu.ee/posts/2026/11/19/unsafeguards/) by a senior product engineer hit [534 points on HN](https://news.ycombinator.com/item?id=50562262). The author had asked Claude Code for low-hanging security fixes in their own project and got stopped by safeguards. The exemption process means waiting "multiple business days", forfeiting data retention exemptions, and handing over an ID or passport. Commenters called it "[a protection racket or as close as makes no difference](https://news.ycombinator.com/item?id=50562568)", and one [suggested](https://news.ycombinator.com/item?id=50562505) paying for Chinese open-weights models instead.

**Also:**

- [OpenSSL CVE-2026-121481](https://github.com/openssl/openssl/pull/33652), a buffer overflow in `EVP_EncodeBlock()` rated CVSS 9.8 that HN commenters say affects OpenSSL 4 only. A contributor on the PR argued "the report's reproducer is completely synthetic, and probably should not be a CVE without evidence it really happens."
- [PostgreSQL 19](https://simonwillison.net/2026/Nov/19/postgresql-19/) shipped two months late, which Simon Willison attributes mainly to "the ongoing AI-reported vulnerability apocalypse". Simon's favorite feature is `WAIT FOR LSN` for read-your-writes consistency on standbys.
- [Token fraud](https://simonwillison.net/2026/Nov/20/token-fraud-is-here-and-its-bad/): Claire Vo is ending ChatPRD's free trials after groups looped trials and promo codes to resell its agent. One of them was a Roblox and Fortnite map studio. Simon noticed the abusers were sending pelican-on-a-bicycle SVG prompts, probably to identify the underlying model.
