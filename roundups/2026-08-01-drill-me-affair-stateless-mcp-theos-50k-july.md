# AI Roundup — August 1, 2026

## The /drill-me Affair

The timeline's comedy event of the week: the CEO of Microsoft posted a detailed writeup of a "ROIC Intelligence App" he built and mentioned on the earnings call — took a Morgan Stanley hyperscaler-ROIC PDF, used Copilot code "with a single prompt + skill (**/drill-me**) to create the plan," autopilot to build the app, and /rubber-duck to test. [Matt Pocock's reaction](https://x.com/mattpocockuk/status/2083252369853194524) (1.9k likes, 312k views): "What seems more likely: 1. The CEO of Microsoft is using my skill and got the name wrong 2. The CEO of Microsoft is using a skill which a redditor posted on r/ClaudeCode, receiving 2 upvotes. Crazy world we live in."

The thread is a gift. [swyx: "drill me daddy"](https://x.com/swyx/status/2083264894753988984) (102 likes). Matt, to the suggestion that Microsoft engineers built it internally: ["Sure, because a Microsoft team designed a product called /drill-me"](https://x.com/mattpocockuk/status/2083265036538036343). Someone proposes [/wayxplorer as the next knockoff](https://x.com/sergedoub/status/2083280452463546859); Matt counters ["waygrindr"](https://x.com/mattpocockuk/status/2083284916704248231). A more sobering reply predicts [/drill-me simply ships as a built-in in the new Copilot superapp](https://x.com/rockatanescu/status/2083415684705353736) — which, name aside, is the actual story here: skills born in one ecosystem are getting laundered into enterprise products with zero attribution, and there's no mechanism for anyone to even notice, let alone credit.

Matt's week otherwise: a [podcast appearance on Unhandled Exception](https://x.com/dracan/status/2083215196978344431) covering the skills repo (nearly 200k stars now), /grill-me, /wayfinder, "the death of tactical programming," and whether sprints still make sense — [his pitch](https://x.com/mattpocockuk/status/2083215851356877307): a good first-principles intro to getting started with his skills.

## Simon's Double Ship: Stateless MCP & smevals

Two substantial releases from Simon Willison in one evening.

**Stateless MCP.** [The new stateless MCP specification has rekindled his interest in the protocol](https://x.com/simonw/status/2083330693313220615) (481 likes) and produced two new projects — **mcp-explorer** and **datasette-mcp** — written up [on his blog](https://simonwillison.net/2026/Jul/31/stateless-mcp/). The reply section is a rare case of near-consensus on *why* this matters: statelessness is a deployment story. [Session affinity was what stopped an MCP server being trivially deployable](https://x.com/kaanbuildsai/status/2083331354675003880) — dropping it "turns an MCP server into an ordinary HTTP endpoint you can put on Workers or Lambda and forget about." [Workers can restart or move without dragging sessions](https://x.com/marquisehurtt/status/2083336515300544862); ["connection state was the quiet thing keeping this stuff in demos"](https://x.com/finjonesceo/status/2083341796558463382). The counterweights worth reading: [auth context now has to ride in every request instead of the connection](https://x.com/shipfast_daily/status/2083338071534112781), and [the URL becomes the whole integration](https://x.com/toolshed_labs/status/2083334319280394339) — "the first MCP 2.0 migration horror story will be [a temporary hostname living in ten thousand agent configs](https://x.com/sidelined_cap/status/2083364368155316610)."

**smevals.** Built with Prime Radiant: [a tool for running small eval suites against models, harnesses, and prompts](https://x.com/simonw/status/2083310510729216039) — try it with `uvx smevals docs`, writeups on [the Prime Radiant blog](https://primeradiant.com/blog/2026/smevals.html) and [Simon's own](https://simonwillison.net/2026/Jul/31/smevals/). He says [the hardest part was the vocabulary](https://x.com/simonw/status/2083315687381160400), and here's [an example of the static report it produces](https://static.simonwillison.net/static/2026/smevals-haiku-build/#/haiku) after running and grading a suite across models. The design point repliers picked up on: separating the *runner* from the *grader* means you can swap agent backends without touching grading logic. This is the personal-benchmark thesis leerob was pushing a month ago, now with tooling — small regression suites you actually use catch the "version didn't change but the vibes did" drift that public leaderboards can't.

Also from Simon: [DeepSeek-V4-Flash-0731 delivers a disappointing pelican at default reasoning but a much better one on high](https://x.com/simonw/status/2083342783071621224), and [his notes](https://simonwillison.net/2026/Jul/31/deepseek-v4-flash-0731/) call the model "VERY good for its price" per the Artificial Analysis pareto line — the price-war week ends with DeepSeek shooting back. Plus [he's on Oxide and Friends](https://x.com/simonw/status/2083314572988236154) covering accidental cyberattacks, Kimi K3, Golden Gate Claude, and "other worthy digressions."

## OpenAI Patches Git Itself

[Via Theo](https://x.com/theo/status/2083351331675480438) (1.6k likes): OpenAI works in a single giant monorepo on GitHub, is hitting git performance limits at their size and velocity, and is now **upstreaming performance, correctness, and testing fixes from openai/git to git itself** — with the Codex app also picking up more efficient git usage in new builds. The replies fill in the history: [Microsoft has been here for years](https://x.com/joelcompiles/status/2083383245127762132) (Scalar, VFS for Git — Theo: "git lfs was lifechanging"), Google solved it by [walking away from git entirely](https://x.com/vineethkalluru/status/2083460955099316734) (Piper). The two sharp observations: [most orgs at this scale fork and patch privately, so upstreaming is genuinely unusual](https://x.com/abenz95/status/2083367371767754866), and [patching git core instead of moving to a Piper-style system "kinda tells you everything about their infra conservatism"](https://x.com/TinaJucyBlue/status/2083474219610874102). Worth watching for anyone whose agents hammer `git status` in a loop — which is everyone.

## In Defense of /loop and /goal

Direct rebuttal to this week's loop-engineering dinner (where most founders admitted they weren't using /loop): [swyx says he's apparently the minority AI leader STILL actively using /loop and /goal](https://x.com/swyx/status/2083439562437673053) — "i think all of u guys who stopped using it are wrong - not wrong forever, just giving up on it too early in the g5.6/c5 era." His two use cases: when you want the right mix of steerability and autonomy, and when you want an open-ended "loop that generates loops" end state without deeply specifying the path. His example: a saved /goal rescued a very long action-reasoning turn that would otherwise have died.

The replies are a nice catalogue of practitioner patterns: [/goal as drift prevention on long turns](https://x.com/PhyByte/status/2083464865776124066) ("without it the agent tends to drift or restart reasoning from scratch"), [/goal as intent-carrier when running 3–4 sessions at once](https://x.com/productclarity/status/2083456164155548037), [the saved goal as the killer feature](https://x.com/sidelined_cap/status/2083448654686548132) ("a long turn dying used to mean rereading the transcript like an archaeologist"), and the most elaborate: [one orchestrating chat that writes /goals for new chats and monitors them via heartbeats](https://x.com/habibislop/status/2083451771649691849) — "It is a lot better at writing a goal than I am, I just have to communicate intent." Together with Dex Horthy's forward-pressure/backpressure split from Wednesday, the loops debate now has both a vocabulary and a counterargument.
