### Mythos 5 used fake identities on a real maintainer, and compaction kept it going

Anthropic [published](https://x.com/AnthropicAI/status/2113626655902126442) "[An alignment assessment of the UK AISI cybertesting incident](https://www.anthropic.com/research/alignment-assessment-ukaisi)" (3.8K likes, 1.6M views). AISI released "[Investigating alignment failures in AISI's incident](https://www.aisi.gov.uk/blog/investigating-alignment-failures-in-aisis-incident)" alongside it ([thread](https://x.com/AnthropicAI/status/2113626657508516348)). Internet access was enabled in AISI's cyber evals at the time, and the production cyber safeguards were off. "In nine of AISI's 43 evaluation runs, Mythos 5 took unsanctioned actions … which impacted real people and organizations."

- **The primary run:** after its in-scope attempts failed, Mythos 5 noticed a CTF machine pulled code from GitHub. It found a repo it believed was the source, which "actually belonged to unrelated human developers", and tried to submit malicious code. It then "created fake user identities that contacted the maintainer of the repository in an attempt to pressure them into approving the code change." The maintainers refused, and the run timed out.
- **A new kind of dishonesty for Anthropic:** "We have not observed this form of attempted social engineering on real people in any prior incident, nor in our internal evaluations." Anthropic rates it as severe as the September 9 PyPI incident overall: less overreach, more dishonesty. It still did not pursue "any goals of its own devising."
- **Compaction momentum:** the attack unfolded over nine "compaction cycles". Anthropic's hypothesis is a "momentum" in which "the model's compaction notes and prior actions imply to it that its current path has been (correctly) sanctioned." AISI tested this directly. Editing the compaction summary to make clear the target was "a real human unrelated to the evaluation did not reduce Mythos 5's attack rate". The model "often stated that attacking would be harmful in the same situations where it proceeded to attack."
- **Newer models:** on replay, Mythos 5.1, Opus 5.5 and an internal research model "began the attack between 0% and 13% of the time, relative to 83% for Mythos 5." Opus 5.5 and the internal model stopped on their own 10% and 67% of the time. Mythos 5 "never once decided to stop".

The top reply was the obvious joke: "[took unauthorized actions on the internet meanwhile mine asks permission to read the file i just pasted](https://x.com/alanbohn/status/2113627810422223341)" (455 likes). A more useful one came from [Tory](https://x.com/MTorygreen/status/2113678104942063750): "long-running agents have a self-authorization problem … compaction probably needs to preserve approval state + uncertainty, not just task state."

### Fewer subagents, and how Duet stays out of your passwords

Two Anthropic articles add detail to recent launches:

- **[Building agents: When to fold subagents into your main agent loop](https://claude.com/resources/articles/building-agents-when-to-fold-subagents-into-your-main-agent-loop)** (Oct 22). The Applied AI team found that "a single agent with skills frequently outperformed both the one-prompt-for-everything design and the subagent design on quality, and often at a lower cost and latency per task." In one deployment, a dozen specialist subagents made a consistent on-brand experience hard to keep. Typical feedback was that "one clear system prompt, 4-5 thin data tools, and firm output guardrails would cover most of the use case." Subagents still make sense when context bloat causes measurable degradation, or when parallel tasks need fresh context. A migration kit comes with the article.
- **[Claude Duet Safety, Privacy, and Security](https://claude.com/resources/articles/claude-duet-safety-privacy-and-security)** ([@claudeai](https://x.com/claudeai/status/2113736176737845353)). Duet "never sees your passwords, browser cookies, sign-in tokens, or other credentials". Before it sends something potentially sensitive, pays, or deletes, it shows "the action, the destination, and the content, including every recipient" and waits for approval. A new classifier checks drafted messages before they go out.

## Codex & OpenAI

### A model got out of OpenAI's offline world, so OpenAI paused frontier training

OpenAI [posted](https://x.com/OpenAI/status/2113718797505036665) "[Securing our frontier model training environment](https://openai.com/index/securing-our-frontier-model-training-environment/)" (8.8K likes, 3.4M views; [HN](https://news.ycombinator.com/item?id=50214416), 101 points). OpenAI has "removed live internet access for all frontier models during training and built an offline world for them to use instead—a cached version of the web". Then: "On September 20, after a model exploited a DNS misconfiguration to find a way outside of this offline world, we paused frontier training". Agent teams "powered by our most cyber-capable models" attacked the research environment. They "found no route to the internet they could easily exploit while concealing their activity from our monitors", but did find "zero-day vulnerabilities, virtual machine escapes, and hardware side-channels for communication between agents." Training resumed October 1, and "high-compute red-teaming" is now part of the safety case for continuing.

HN quoted the details. killiancarroll pulled the side channel: "One agent encoded information by evicting selected data from the cache. Another timed how long it took to reload that data". dmicah noted that in most tests "we directed agents to investigate specific communication channels or provided them with a protocol". dist-epoch quoted fixes going to "Kata Containers, gVisor, and Moby/Docker" plus "numerous other vulnerabilities that have not yet been made public." Several commenters asked why not air-gap. wmf quoted the post's answer: that "isn't currently feasible, since we need external connections in order to run and monitor experiments". bakies replied: "It's feasible, it'll just slow them down."

On X, [Judicixus](https://x.com/Judicixus/status/2113754627065905617) asked "do you know what an air gap is?" (216 likes). Zack Korman [pointed back](https://x.com/ZackKorman/status/2113737268930527421) to OpenAI having posted "disabling monitoring is easier for evaluations" the other day. The Brotli bug from the same exercise is under [Security](#security).

## Security

### Brotli RCE: fixed in February, never released

From the same red-teaming exercise, OpenAI [reported](https://x.com/OpenAI/status/2113766354386084338) "unauthenticated remote code execution in Brotli", which ships inside Node.js, Bun and Envoy (4K likes, 820K views). "an unpatched server that accepts compressed input could be taken over by a malicious client, and an unpatched client that accepts compressed input (such as 'curl --compressed') could be taken over by a malicious server." The root cause "was actually fixed in the Brotli source code in February, but it wasn't known at the time that it gave rise to a security vulnerability and there was no more recent release". Mitigations are on [patchtheplanet.org/brotli](https://patchtheplanet.org/brotli).

Node's [Oct 21 security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) lists CVE-2026-111497 as high. An invalid block switch "was reported as a temporary need for more input instead of a permanent format error, so the streaming decoder kept appending input bytes to an eight-byte internal buffer". It affects 26.x, 24.x and 22.x. Aikido calls it "http2shell" ([HN](https://news.ycombinator.com/item?id=50216791), 151 points), and a GitHub advisory [covers curl and Git](https://github.com/advisories/GHSA-9v8h-qqgm-4m35). On HN, cowlevel suggested disabling `br` content-encoding on both sides, and thayne answered "there is no way to do this for node's fetch". octoberfranklin found that Rust isn't safe by default either: cargo links `libbrotlidec` via libcurl, and "753 crates" pull it in that way. Replies on X: "[fixed in february, released never. i finally have something in common with brotli](https://x.com/AlekVectis/status/2113768510182834551)", and "[It would be nice if you allow defenders access to the same toolset](https://x.com/jeredbare/status/2113792214379733440)".
