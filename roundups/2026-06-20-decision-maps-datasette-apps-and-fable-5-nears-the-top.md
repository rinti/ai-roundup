# AI Roundup — June 20, 2026

## Pocock's Decision Maps — Planning as Parallel Grilling

**The new skill.** Matt Pocock is iterating on a new planning technique he calls **decision maps**. The idea: before writing code, run a short grilling session to identify the *frontier* of unresolved decisions, then fan out to multiple parallel sessions — each one exploring a different branch of the decision tree through grilling, prototyping, or research. [He laid out the concept (June 18)](https://x.com/mattpocockuk/status/2067602690725581067): "Playing around with the idea of decision maps — 1. Figure out the 'frontier' of decisions with a short grilling session. 2. Fan out to multiple grilling/prototyping/research sessions, uncovering the fog of war as you go." He showed himself grilling on three aspects of a large build simultaneously.

**The proof.** A day later he posted the output: [an "absolute monster PRD" built from a /decision-mapping session](https://x.com/mattpocockuk/status/2068003650849362323), featuring a course agent with write-back editing via approval-gated VFS diffs and a fixed sidebar. The workflow — grilling → decision map → PRD → issues — is the most structured version of his planning pipeline yet, and it builds directly on the /write-a-prd and /prd-to-issues skills from [his earlier workflow](https://x.com/mattpocockuk/status/2024874219662905676).

**Context: Skills v1.** This all lands a few days after [mattpocock/skills v1.0.1 shipped (June 17)](https://x.com/mattpocockuk/status/2067259590488510471), which achieved a **63% reduction in token cost** via progressive disclosure, split skills into model-invocable vs user-invocable categories, and added /codebase-design, /domain-modeling, and /grilling. The repo has 135K+ stars and 11.7K+ forks — the most-starred Agent Skills collection on GitHub.

## Datasette Apps — Claude Artifacts for Your Database

**What shipped.** Simon Willison launched [Datasette Apps (June 18)](https://simonwillison.net/2026/Jun/18/datasette-apps/) — a plugin that lets you host custom HTML+JS applications inside an iframe sandbox within Datasette, with access to a JSON API for the full relational database underneath. He described it on [Mastodon](https://fedi.simonwillison.net/@simon/116773839324991241) as **"Claude Artifacts reimagined for Datasette"** — the power of artifacts, plus a database you can read from *and* write to.

**The LLM angle.** The plugin itself has no dependency on LLMs, but Willison notes these self-contained apps are *"the perfect shape to be written by a modern LLM."* Copy a prompt, paste it into ChatGPT/Claude/Gemini, describe what you need, and the model generates the code. If [Datasette Agent](https://simonwillison.net/2026/May/21/datasette-agent/) is installed, the AI assistant gains tools to create and edit apps inline, Claude Artifacts–style. The goal: full read-write applications built safely as Datasette Apps.

**The broader Datasette sprint.** This is part of a prolific June for Willison: [datasette-agent 0.2a0 (June 10)](https://simonwillison.net/2026/Jun/10/datasette-agent/), [datasette-agent-edit 0.1a0 (June 7)](https://simonwillison.net/2026/Jun/7/datasette-agent-edit/), [datasette 1.0a33 (June 11)](https://simonwillison.net/2026/Jun/11/datasette/), and a [Datasette extras explorer tool (June 11)](https://simonwillison.net/2026/Jun/11/datasette-extras-explorer/). The agent + apps stack is becoming a full platform for LLM-driven data exploration.

## Fable 5 Enters Terminal-Bench at 83.1%

**The leaderboard.** Claude Code + Fable 5 entered [Terminal-Bench 2.1](https://www.morphllm.com/best-ai-coding-agents-2026) on June 17 at **83.1%** — within 0.3 points of the leader, Codex + GPT-5.5 at 83.4%. Claude Code + Opus 4.8 sits at 78.9%. The gap between the top two is now razor-thin, with the competition increasingly about harness design rather than raw model capability.

**Fable 5 benchmarks in context.** Across other benchmarks, Fable 5 scores [80.3% on SWE-Bench Pro](https://www.mangomindbd.com/blog/claude-fable-5-benchmarks) and [95% on SWE-bench Verified](https://www.morphllm.com/claude-benchmarks). The model's availability remains limited by the US Commerce Department's export-control directive from June 12, which required Anthropic to [suspend access for foreign nationals](https://andrew.ooo/answers/claude-fable-5-us-only-workarounds-for-non-us-developers-june-2026/) — a saga that caught up even Karpathy (who holds an EB-1 green card, making him exempt).

## Still Reverberating — Loops, Subagents & Openness

**Nested subagents, depth 5.** Boris Cherny [shipped nested subagent support in Claude Code v2.1.172 (June 9)](https://x.com/bcherny/status/2064327225504403752), capped at depth 5. The motivation is context management, not parallelism — each subagent gets a fresh context window, so nesting lets a sub-agent offload before its own context fills. In Cherny's words: *"agents kicking off agents as a way to better manage context."* The restriction that sub-agents couldn't spawn other sub-agents is now gone. Several [guides](https://ofox.ai/blog/claude-code-nested-subagents-2026/) and [tests](https://newsletter.owainlewis.com/p/i-tested-nested-subagents-in-claude) have emerged in the days since.

**Thariq's Fable-edits-its-own-video walkthrough keeps spreading.** [Thariq (@trq212) posted a demo (June 11)](https://x.com/trq212/status/2061545633560010826) showing Fable 5 editing its own launch video — 25GB of raw footage from 17 takes, no video editor opened. Three prompts: one for initial shot selection and ffmpeg cuts, one for color grading via hand-written .cube LUT files, and one for motion graphics using Figma MCP + Remotion rendering. The [interactive deck](https://thariqs.github.io/cc-video-editing-deck/) and a [6:39 follow-up video](https://x.com/trq212/status/2061545633560010826) have been doing the rounds. Karpathy [RT'd it](https://x.com/karpathy/status/2061928642029158853). Thariq also shared his [dynamic workflows post](https://x.com/trq212/status/2061907337154367865) about building custom harnesses for each task.

**"Gaslighting Openness."** Armin Ronacher's [June 10 blog post](https://lucumr.pocoo.org/2026/6/10/gaslighting/) is still circulating. He argues that AI companies wrap access restrictions in safety and security language while training on public work and blocking open-source attempts to learn from these systems. Open source, he writes, is being stressed by AI slop, shifting contributor dynamics, the falling cost of producing code, and large companies learning to close doors behind them. This follows his earlier provocative take that [AI agent workflows create a dopamine-driven loop that feels productive but produces low-quality output](https://x.com/mitsuhiko/status/1992236433751613588), and his February blog post exploring [programming languages designed specifically for agents](https://lucumr.pocoo.org/2026/2/9/a-language-for-agents/).

Core thesis: *"vibe coding raised the floor, agentic engineering raises the ceiling."* The [Sequoia playlist](https://www.youtube.com/playlist?list=PLOhHNjZItNnOkkZThzULo1Ygg7JR6T3MG) includes talks from Karpathy, Demis Hassabis, Jim Fan, and Boris Cherny.
