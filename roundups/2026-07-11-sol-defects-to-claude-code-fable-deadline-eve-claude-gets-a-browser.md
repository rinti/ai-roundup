# AI Roundup — July 11, 2026

## The Harness Flip — Sol in Claude Code

Theo spent the evening wiring gpt-5.6-sol into Claude Code, live-tweeting the experiment from ["Trying something real quick (look closely at the top)"](https://x.com/theo/status/2075757587010929003) through ["Holy shit it's working"](https://x.com/theo/status/2075758118747955464) to the conclusion that broke containment:

- **"gpt-5.6-sol is meaningfully better in Claude Code than in Codex. I'm going to crash out so badly over this"** ([post](https://x.com/theo/status/2075776733626892542), 138K views, 2.2K likes). The specifics: [it makes better *designs*](https://x.com/theo/status/2075776895292248173) ("WHY. WHY IS IT BETTER AT DESIGN WHEN USED IN CLAUDE CODE"), Claude Code's workflows use [way fewer tokens than Codex Ultra for the same output quality](https://x.com/theo/status/2075777990689190297), and Claude Code's subagent orchestration is ["significantly better than Codex's… Turns out code is good, and sol is good at writing code!"](https://x.com/theo/status/2075765314483376285) Asked whether this changes his opinion on custom harnesses: ["Kind of? I have very complex thoughts here. Video coming soon. Codex fork hopefully not coming after but it might have to..."](https://x.com/theo/status/2075788139764060246)

- The replies are a snapshot of the harness-hopping era: ["It's kinda ironic at this point that for almost every lab's models, they tend to perform better in other labs' harnesses"](https://x.com/CampuzanoJoe/status/2075777093502222581), ["Harnesses get WAY less attention from labs than they should"](https://x.com/kisimanakucha/status/2075789059994087839), and the counter-report that [Fable is meaningfully better in Codex](https://x.com/2nic3/status/2075789056961585643) for backend/long-running work — the flip apparently goes both ways.

- **The concrete Codex fumble that started it**: [if you set gpt-5.6-sol to "ultra", every subagent it spawns is also Ultra](https://x.com/theo/status/2075742083370127504) (186K views) — the `spawn_agent` tool doesn't let the model choose effort level, so quota evaporates three layers deep. Best war story in the replies: a user who ran Sol Ultra overnight and [woke up to an $800 auto-pay surprise and a folder full of spec files](https://x.com/brodieacc/status/2075781144881012828) — "the red-team subagent spent 8 hours finding increasingly ridiculous non-issues in the scaffold. Zero actual code built." Theo's one-word reply: "Accurate." Rambone's summary deserves framing: ["Subagents should default to Luna. Why are we paying the PhD researcher to do a grep."](https://x.com/vinrambone/status/2075768702415389010)

- There *is* a partial workaround — hidden config flags. Eidzoku shared the [`[features.multi_agent_v2]` incantation](https://x.com/evi77ain/status/2075743725817606587) (`hide_spawn_agent_metadata = false`, `tool_namespace = "agents"`), which Theo [confirmed is required](https://x.com/theo/status/2075752595617181809) before subagent metadata even passes through, while [dismissing the "just define roles in config" defense](https://x.com/theo/status/2075757941756727689): "The whole point is that the model can right-size the subagent orchestration depending on the task." Codex's [v2 subagent implementation is still cooking](https://x.com/theo/status/2075742454188585005), and 5.6 [seems to trigger an auto-upgrade to it](https://x.com/theo/status/2075746766734180779) — "a rat's nest." OpenAI's eric provencher replied ["We're working on this"](https://x.com/pvncher/status/2075745362174693638); Theo: ["Please do. I want workflows so badly."](https://x.com/theo/status/2075747197552066680)

## Fable's Deadline Eve

Tomorrow is July 12 — the announced end of Fable 5 access in Claude Code plans — and the mood shifted from mourning to game theory.

- **Theo's take got 4.7K likes**: ["I would like to thank OpenAI for putting out a model exactly good enough to force Anthropic to keep bundling Fable in the Claude Code plan"](https://x.com/theo/status/2075768231403667645) — with the caveat that [the cutoff is still probably happening](https://x.com/theo/status/2075774654476922986), "but it would be insane for them to go through with it."

- The replies are a betting market: [Polymarket gives an extension 37%](https://x.com/Michaelzsguo/status/2075775600636150080) (Michael Guo thinks it's higher), one reply calls [95%+ odds of an extension by the 13th](https://x.com/Gabriel78470020/status/2075805201471098916) "from a game theory perspective," another predicts they'll [keep adding a week at a time until the next Fable model is ready](https://x.com/MaaSonder/status/2075778503686173183). The maximalists want more: ["gonna need them to allow fable for 100% of the usage limits now"](https://x.com/kr0der/status/2075768670404714794) (currently capped at 50%), and ["If they go through with it prepare for mass dumping of Claude accounts"](https://x.com/juleshatton/status/2075811168896143640). The defection case is also represented: ["OpenAI has been very generous with their usage resets… It has also caught and fixed several things that Fable 5 did not. I will not be paying extra for Fable 5."](https://x.com/MerelyJeremy/status/2075786570116792364)

## Claude Code Gets a Browser

- **Claude Code on desktop now has a sandboxed in-app browser** ([ClaudeDevs announcement](https://x.com/ClaudeDevs/status/2075635283211772279), 1.7M views, 16K likes): Claude can pull up docs, designs, or any site, read and click through them the same way it interacts with your local dev servers, and you choose whether sessions persist. RT'd by both Boris Cherny and Thariq. The replies capture the range: ["watching it click through docs and actually USE them is wild"](https://x.com/pawzzard/status/2075648639150559677), the timing jab — ["takes special kinda balls to release this the day after OpenAI sunset Atlas"](https://x.com/RiverKhan/status/2075643956268872120) — and the counterpoint that [OpenAI's new ChatGPT app shipped its browser with password/cookie import a day earlier](https://x.com/mdavidcyrus/status/2075675364236406816). One practical gotcha already surfaced: it apparently [broke someone's Playwright MCP setup](https://x.com/talirezun/status/2075652252736381251) in the desktop app.

- **Simon Willison reads the Atlas retirement as a category ending** ([post](https://x.com/simonw/status/2075661863757746535)): "With Atlas being retired in favor of the browser embedded in the ChatGPT app I wonder if the whole category of AI-enhanced browsers is coming to a close. The security/privacy issues remain unsolvable IMO — I want my AI to use its own separate browser and stay out of the one I use." Notably, that's exactly the architecture both labs converged on this week: the agent gets its *own* sandboxed browser rather than driving yours.

## Codex vs. Work — The Confusion Continues

Simon Willison kept pulling on yesterday's ChatGPT-app thread and got somewhere useful:

- **Is Codex a strict superset of Work Mode?** ([post](https://x.com/simonw/status/2075663976453808222), 81K views) The crowd consensus: yes for engineers — ["work mode is for anyone who is intimidated by git"](https://x.com/shuv1337/status/2075665443663274236) — and [OpenAI insiders say the split is purely UI, not capabilities](https://x.com/simonw/status/2075696361803317574). The most substantive defense of Work Mode's existence: [enterprise employees often literally can't install git](https://x.com/nathanclement/status/2075674398842106321), and a VM-sandboxed "Work" surface is what gets ChatGPT deployed org-wide instead of engineers-only.

- **Except it's not purely UI**: Simon found that in the mobile app, [Work mode can run code that talks to the Internet while Chat mode can't](https://x.com/simonw/status/2075740417220616394) — he had both modes try `yt-dlp` to extract YouTube subtitles; it failed in Chat and worked in Work. Also noted: [Sol on Medium might be the new default for coding](https://x.com/simonw/status/2075663372323008755) (vs. his previous favorite, 5.5 xhigh), and the app is [bringing chats and projects back into the sidebar](https://x.com/simonw/status/2075660468140826719) — "hopefully that means classic chat won't hide in that weird little floating window any more."

## Agentic Coding & Craft

- **pi lands dynamic tool loading without cache wiping** ([Armin Ronacher](https://x.com/mitsuhiko/status/2075703856726499364), 431 likes): the next release loads tools mid-session without invalidating the prompt cache, with "somewhat consistent API behavior between OpenAI and Anthropic." The mechanics, [from his replies](https://x.com/mitsuhiko/status/2075724007026880863): adding tools works, removing them still wipes caches ("just fundamental limitations"), and the use cases are progressive disclosure of tools plus clean state transitions (Plan → Implement). He [tried a generic `dynamic_call` fallback tool](https://x.com/mitsuhiko/status/2075834904575709678) but found smaller models handle it poorly, so DeepSeek falls back to cache-trashing. Best reply-summary of why this matters: ["Give the model 200 tools and it guesses. Give it the 12 it needs right now and it behaves more like a coworker."](https://x.com/Ferbin08/status/2075787678755270673) Related Armin envy: ["I would kill to know what the codex backend is doing."](https://x.com/mitsuhiko/status/2075563568875950557)

- **Matt Pocock's durable case for skills** ([post](https://x.com/mattpocockuk/status/2075569153633575151)): "To me it feels like I'm trying to build good software practices, and the distribution mechanism is skills. My bet is that good software practices haven't changed and likely won't change very much." The sharpest reply cuts the other way: one team [had to redesign most of their skills after Fable shipped](https://x.com/vadimcomanescu/status/2075711857558421934) because they were "actually making the model dumber" — coding skills may get absorbed by the models ("3 months ago telling a model to tdd was relevant, nowadays not so much"). Counter-signal from another reply: [5.6 Sol proactively invokes skills better than any other model](https://x.com/rohan10/status/2075571792974925849), which makes good skills *more* valuable. Matt also shipped [a run-once skill that sets up deep-module package boundaries in any TypeScript codebase](https://x.com/mattpocockuk/status/2075505624096350655) (imports only via `<name>/index.ts`), is [considering his own skills-install CLI](https://x.com/mattpocockuk/status/2075495703028142364) for per-agent customization and dependency tracking, and is [polling on an official slide-deck template](https://x.com/mattpocockuk/status/2075695331942043774) for people giving internal talks about his skills.

- **What 2,300 tokens/sec feels like** ([LLMJunky](https://x.com/LLMJunky/status/2075690637010022860)): he built *Damage Scout* with the Gemma team — Gemma 4 on Cerebras sampling frames from a rental-car walkaround video and rendering an annotated damage report in under 6 seconds. "You have to be much more deliberate about your prompting because there's no steering 2,000 TPS… Tool calls become the bottleneck." His tip for trying fast models in a coding agent: [use OpenCode, since Cerebras is stateless and OpenCode manages session history for you](https://x.com/LLMJunky/status/2075694938021396907).

- **PSA of the day**: after someone's agent trashed files outside the repo, dabit3's [widely-RT'd fix](https://x.com/dabit3/status/2075673686695453158) is a global PreToolUse hook that hard-blocks any command touching paths outside the repo (works even in yolo mode), with `permissions.deny` rules as backup. LLMJunky demonstrates the no-docs version: ["Hey Codex, create a global PreToolUse hook that blocks destructive commands"](https://x.com/LLMJunky/status/2075766495376818678) — "Do not RTFM. Just PTFC."
